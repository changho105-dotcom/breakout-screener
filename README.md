# 돌파매매 스크리너 (1단계 MVP)

코스피/코스닥 + 미국주식(S&P500)을 대상으로 돌파매매 체크리스트를 자동 채점하는 스크리너.

## 체크리스트 → 지표 매핑 (lib/indicators.js)
1. 시장 상승추세 → 지수 20일/60일선 기준 국면 분류 (STRONG_UP/WEAK_UP/PULLBACK/DOWN)
2. 신고가 근접 → 기준기간(선택 가능) 최고가 대비 -20% 이내인지 (예전 RS 자리를 대체)
3. 거래량 급증 → 당일 거래량 / 20일 평균거래량 ≥ 1.5배
4. 전고점 돌파 → 기준기간 최고가(당일 제외) 돌파 여부, 손절선은 베이스 하단(또는 % 대체) 기준

체크리스트 통과 개수가 0~4점으로 점수화되어 정렬됩니다.

**유동성은 체크리스트가 아니라 하드 필터입니다.** 20일 평균 거래대금이 기준(국내 5억원/미국 $5M) 미달인 종목은
체크리스트 판정을 아예 받지 않고 결과 목록에서 제외됩니다 (실제 체결이 어려운 종목이라 강도 판단 자체가 무의미하다고 판단).

⚠️ 20일 박스권 돌파 → 36주 전고점 돌파로 기준을 바꾸면서 신호 발생 빈도가 크게 줄어듭니다.
36주 신고가 돌파는 원래 훨씬 드문 이벤트라, 스크리너에 뜨는 종목 수 자체가 적어지는 게 정상입니다.

## 신고가/돌파 기준 기간 선택
화면 상단 드롭다운에서 60일 / 120일 / 36주 / 52주 중 선택 가능합니다 (스크리너·백테스트 공통 적용).
바꾸면 해당 기간 기준으로 즉시 다시 계산됩니다. 옵션 추가/조정은 `lib/indicators.js`의 `LOOKBACK_OPTIONS`에서.

## ⚠️ 배포 전 꼭 확인해야 할 것 (샌드박스에서 검증 불가능했던 부분)

개발 환경(샌드박스)에서 `finance.naver.com`과 `stooq.com` 접속이 네트워크 정책상
막혀 있어서, 아래 두 가지는 **실제로 살아있는 응답을 받아본 적이 없습니다.**
로직 자체(지표 계산)는 가짜 데이터로 단위 테스트를 거쳤지만, 크롤링 파싱 부분은
Railway에 올린 뒤 직접 호출해서 확인해주세요.

- `lib/krSource.js` — 네이버 금융 HTML 테이블 구조(`table.type_2`, `a.tltle`)가
  바뀌었다면 `fetchStockList`가 빈 배열을 반환합니다.
- `lib/usSource.js` — stooq.com의 CSV 응답 형식이나 심볼 규칙(`.us` 접미사,
  지수 심볼 `^spx`)이 다르면 `fetchOHLCV`/`fetchIndexOHLCV`가 빈 배열을 반환합니다.

둘 다 빈 배열이 오는 형태로 "조용히" 실패하니, 배포 후 아래로 직접 호출해서
`stocks` 배열이 비어있지 않은지 꼭 확인하세요:

```
GET /api/screen/kr
GET /api/screen/us
```

## 미국장 관련 참고
- 종목 유니버스를 S&P500 단독에서 **다우30 + 나스닥100 + S&P500** 통합(중복 제거)으로 확장
  (다우30/나스닥100 리스트: yfiua.github.io/index-constituents, S&P500+섹터: datasets/s-and-p-500-companies)
- 지수는 S&P500(^GSPC)/다우(^DJI)/나스닥종합(^IXIC) 3개를 각각 계산해서 화면에 게이지로 표시
- 다만 개별 종목의 RS·포지션비중 계산 기준 지수는 **S&P500 하나로 통일**했습니다(다우·나스닥은 참고용 게이지). 종목마다 소속 지수 기준으로 따로 계산하려면 추가 작업이 필요해서 지금은 단순화한 상태 - 필요하시면 다음 단계에서 분리 가능
- OHLCV 소스를 stooq.com에서 Yahoo Finance Chart API로 교체함
  (stooq가 Railway 같은 클라우드 IP를 차단하는 것으로 보여서 교체)
- 요청량을 줄이기 위해 MVP는 최종 250개 종목까지만 스캔합니다 (다우30·나스닥100은 항상 포함, 나머지는 S&P500으로 채움)
  (환경변수 `US_UNIVERSE_LIMIT`로 조정 가능, Railway → Variables에서 설정)
- Yahoo Finance나 yfiua 데이터셋도 언젠가 막히거나 형식이 바뀔 수 있음 - 이 경우
  `/api/screen/us` 에러 메시지에 원인이 그대로 표시됩니다

## 백테스터 (2단계)
스크리너와 동일한 `lib/indicators.js` 로직을 과거 데이터에 그대로 적용해서 검증합니다.
- 화면의 "백테스트" 탭에서 미국 주식 티커 입력 후 실행 (예: PLTR)
- API: `GET /api/backtest/us/:ticker`
- 진입: 조건 충족 다음날 시가 / 청산: 손절선 터치, 국면 하락 전환, 또는 최대 90거래일 보유 초과
- 매 거래마다 자본 전액을 순차 재투자한다고 가정한 단순 모델입니다 (분할매수/포지션 사이징은 3단계 봇에서 반영 예정)

## 이번에 추가된 4가지 (2026-08-05)

1. **국내 업종(섹터) 데이터** — 네이버 "업종별 시세" 페이지를 크롤링해서 코스피/코스닥 종목에도 섹터 강도가 반영됩니다.
   업종 크롤링은 시간이 걸려서(업종 60~80개 순회) 24시간 캐시로 따로 관리합니다. 실패해도 섹터만 빈 값으로 빠지고 나머지는 정상 동작.
2. **백테스트 거래비용 반영** — 매 거래마다 편도 0.15%(왕복 약 0.3%) 수수료/슬리피지 가정치를 진입가/청산가에 반영합니다.
   `순수익 복리수익률`과 `거래비용 반영 전` 수치를 같이 보여줘서 비용이 얼마나 깎아먹는지 비교 가능. 비용 가정치는 `lib/indicators.js`의 `CONFIG.oneWayTradingCostPct`에서 조정.
3. **여러 종목 백테스트 비교** — 백테스트 입력창에 `PLTR,AME`처럼 쉼표로 구분해 넣으면 승률·손익비·복리수익률·MDD를 한 표로 비교. 티커 하나만 넣으면 기존처럼 상세 거래내역이 나옵니다. API: `GET /api/backtest/us/compare/batch?tickers=A,B,C`
4. **베이스 하단 기준 손절선** — 손절선을 "돌파선의 97%"에서, 돌파 직전 20거래일 구간의 저점(베이스 하단)으로 우선 계산하도록 변경.
   베이스 하단이 돌파선 대비 -15%보다 더 멀면(리스크 과다) % 기준으로 자동 대체됩니다. 화면 손절선 옆에 `(베이스)` / `(%)` 표시로 어떤 기준이 쓰였는지 확인 가능.

## 종목 클릭 → 차트
스크리너 표에서 종목 행을 클릭하면 모달로 차트가 뜹니다 (종가 라인 + 돌파선/손절선 + 거래량 막대).
API: `GET /api/chart/kr/:ticker`, `GET /api/chart/us/:ticker` (lookback 쿼리로 기준기간 반영).
외부 라이브러리 없이 순수 SVG로 그려서 별도 차트 패키지 설치가 필요 없습니다.

## 미너비니(SEPA) 트렌드템플릿 통합 및 정리 (2026-08-05)

기존 4개 체크리스트에 미너비니 요소를 추가했다가, 중복/신뢰도 문제로 일부를 정리했습니다.

**체크리스트(점수 반영)**: 시장국면 · 신고가근접 · 거래량급증 · 전고점돌파 · **트렌드템플릿** · **RS Rating**
- 트렌드템플릿: 현재가>150일선>200일선, 200일선 1개월간 상승, 50일선>150/200일선, 현재가>50일선 (5개 조건을 하나로 판정)
- RS Rating: 현재 스캔 대상 종목군 안에서 수익률 백분위 70+ (스크리너 전용, 백테스트는 단일 종목이라 계산 불가)

**참고용(점수 미반영)**: 52주 저점 대비 상승률, 섹터 강도
- 52주 저점 대비 상승은 신고가근접·돌파와 신호가 겹쳐서 필수조건에서 뺐습니다 (화면에는 계속 표시)
- 섹터 강도(sectorAvgReturn)는 계산은 되지만 필터/점수에는 반영 안 된 참고용 숫자입니다

**제거함**: VCP(변동성 수축 패턴) — 손으로 보는 다중파동 패턴을 정확히 재현하지 못하는 근사치라 신뢰도가 낮아 제거했습니다.

## 대규모 정리 + 기능 추가 (2026-08-05, 2차)

### 뺀 것
- **개별강도(%) 컬럼 제거** — 확인해보니 한 화면 안에서는 시장국면이 전 종목에 동일하게 적용돼서, 점수(score)에서 국면 하나만 뺀 게 개별강도라 사실상 같은 순위를 두 번 보여주는 중복 컬럼이었습니다.
- **저점대비(52주 저점 대비 상승률) 컬럼 제거** — 신고가근접·돌파와 신호가 겹치는 참고용 항목이라 컬럼 정리 차원에서 뺐습니다.
- **안 쓰이는 export 정리** (`sma`, `regimePositionSizeFactor`, `passesLiquidity` 등 — 내부에서만 쓰이고 외부 모듈에서 import 안 하던 것들)

### 넣은 것
1. **국내(코스피/코스닥) 백테스트** — 백테스트 탭에 시장 선택(미국/코스피/코스닥) 드롭다운 추가. `GET /api/backtest/kr/:ticker?market=KOSPI|KOSDAQ`
2. **연도별 성과 분리** — 백테스트 결과에 연도별 거래횟수/승률/수익률 표 추가. ⚠️ 정식 워크포워드 검증(기간별로 파라미터를 다시 튜닝해 아웃오브샘플 검증)은 아니고, 특정 한 해에 성과가 쏠려있진 않은지 보는 간이 버전입니다.
3. **기준 기간별 비교** — "기간별 비교" 버튼으로 60일/120일/36주/52주 4개를 한 종목에 대해 한 번에 비교. `GET /api/backtest/:region/lookback-compare/:ticker`
4. **정렬/필터 UI** — 스크리너 표 헤더 클릭으로 정렬(재클릭 시 오름차순/내림차순 전환), 섹터 드롭다운으로 필터링
5. **데이터 조회 실패 카운트** — 크롤링/API 실패로 조용히 빠진 종목 수를 화면 상단 메타 정보에 표시 (`fetchFailures`) — 소스가 깨졌는지 화면만 보고도 대략 감지 가능

## 체크리스트 대규모 검증 및 변경 (2026-08-06)

미국/KOSPI/KOSDAQ 3개 시장, 여러 기간(6년/15~16년/버블구간 제외 등)으로 조건 하나씩 제거해가며
백테스트한 결과를 반영해서 체크리스트를 정리했습니다. (백테스트는 룩어헤드 버그도 이 과정에서
발견·수정함 — `lib/backtest.js`의 국면하락 청산이 당일 종가로 판정한 걸 당일 시가에 반영하던
버그를 익일 시가 체결로 수정)

### 뺀 것
- **신고가근접 조건 삭제** — "전고점 돌파"에 이미 통과했다는 건 정의상 신고가 근처(-20% 이내)라는
  뜻이라 자동으로 항상 참이 되는 죽은 조건이었습니다. 3개 시장 전부 이 조건을 빼도 백테스트 결과가
  소수점까지 완전히 동일하게 나오는 걸 확인했습니다. (`relativeStrength` 수치 자체는 화면 "고점대비"
  컬럼에 계속 표시하되, 체크리스트 점수에서는 제외)

### 시장별로 다르게 반영한 것
- **시장국면 조건 — 한국은 유지, 미국은 삭제.** 조건 하나씩 제거해보는 검증에서, 미국은 국면필터를
  빼는 쪽이 수익률·MDD가 일관되게 더 좋았고(더 많은 기회를 잡음), 한국은 반대로 국면필터를 빼면
  성과가 크게 나빠졌습니다. 체크리스트가 시장마다 다른 항목 수를 가지게 됩니다 — 한국은 5개
  (국면·거래량·돌파·트렌드템플릿·RS), 미국은 4개(거래량·돌파·트렌드템플릿·RS).

### 확인했지만 아직 반영 안 한 것
- 청산 방식을 "국면하락 시 즉시청산"에서 "20일선 이탈 시 청산"으로 바꾸는 안(포트폴리오 시뮬레이션
  기준 더 나은 결과 확인)은 실험용 엔진(`lib/backtestPortfolio*.js`)에만 구현돼 있고, 실제 스크리너·
  백테스터(`lib/backtest.js`)에는 아직 반영 안 했습니다. 단일종목 백테스터는 여전히 국면하락 즉시청산
  방식입니다.
- "상위 N종목 압축 포트폴리오"(동시보유 종목 수 제한 + RS초과수익 순위 슬롯 배정)도 실험용 엔진에만
  있고 정식 백테스터에는 없습니다.

### 실전 가상매매 트래커 (`paper_trade/`)
2026-08-06부터 30일간, 한화 5천만원(코스피+코스닥) / 달러 5천만원 상당(미국) 두 포트폴리오로 실제
현재 데이터를 매일 스캔해서 가상매매 진행 중. 현황은 `/paper-trade.html`에서 확인 가능.
`paper_trade/daily_update.js`를 매일 1회 실행(자동화 미완성 — 현재는 수동 실행) → 기존 보유 종목
20일선 이탈/손절 체크 후 매도 → 빈 슬롯 있으면 오늘 조건 통과 종목 중 RS초과수익 상위로 채움.

2. Railway에서 새 프로젝트 → GitHub repo 연결
3. 별도 환경변수 없음 (지금 단계는 API 키 불필요 - 크롤링 기반)
4. 배포 후 `/api/screen/kr`, `/api/screen/us` 호출해서 정상 동작 확인
